# CDAS 查询结果导出

适用于 macOS 上的 Chrome 109 或更新版本。可读取 CDAS「运行及展示」中 `selectDg` 结果表格，保存为 CSV、JSON，或复制为可粘贴到 Excel / Numbers 的表格。安装和使用无需 Node.js、Python 或外部服务。

## v1.1.0 · Lens 风格界面

参考 [Lens Showcase](https://ruiqichenbiec.github.io/design-systems/lens/lens-showcase.html)，采用浅灰绿纸面、深绿胶囊按钮、透镜面板和清晰的数据表格。桌面使用左侧读取控制、右侧结果预览布局，窄窗口自动纵向排列。提供键盘焦点、可展开格式说明与减少动态效果支持。

## 安装到 Mac Chrome

1. 下载并解压 `CDAS-Exporter-v1.1.0.zip`。
2. 在 Chrome 地址栏打开 `chrome://extensions`。
3. 打开右上角「开发者模式」。
4. 点击「加载已解压的扩展程序」，选择解压后的 **CDAS-Exporter** 文件夹，文件夹内应能直接看到 `manifest.json`。
5. 点击浏览器工具栏的拼图图标，将「CDAS 查询结果导出」固定到工具栏。

保留该文件夹，后续 Chrome 会从中加载插件。源码开发时也可直接加载本仓库的 `extension` 文件夹。

更新旧版本时，保持原来的扩展文件夹路径，用新版文件替换其中的内容，再在 `chrome://extensions` 点击该扩展的「重新加载」。如果改用了新的文件夹路径，请移除旧扩展后重新「加载已解压的扩展程序」，避免同时安装两个版本。

## 使用

1. 在已登录的内网 CDAS 页面正常执行查询，打开「结果 1」等结果页签。
2. 点击工具栏的插件图标。插件打开独立导出页，自动识别来源标签页及其中的同源查询 iframe，并读取当前页。
3. 多个结果表格可在「结果表格」下拉框中切换。默认优先选择原页面当前可见的结果。
4. 点击「导出 CSV」「导出 JSON」或「复制到表格」。CSV 可用 Excel / Numbers 打开。
5. 需要多个分页时，设置最多页数和行数，点击「从第 1 页连续读取」。结束后再导出。

连续读取不是截图识别：在线页面优先使用 EasyUI 数据缓存，所以即使单元格文字在界面上被列宽截断，也能读取已经加载的完整值。后台本身未返回或已经截断的内容无法恢复。冻结列会合并，行号、勾选框和隐藏列不会导出，重复数据行会保留。

## 连续分页的行为

- 默认最多 100 页、50,000 行；可设为最多 1,000 页、200,000 行。多个请求串行执行，两页之间间隔约 450 毫秒，不修改页面的每页条数。
- 从第 1 页开始。若当前已在第 1 页，先读取该页缓存；否则先调用页面原有分页功能返回第 1 页，再逐页读取。
- 使用页面现有的登录状态、权限与分页回调，不自行拼装 SQL，不直接调用查询接口，不取消或突破服务端限制。连续翻页会像手工翻页一样触发正常查询。
- CDAS 的总行数可能是用于控制下一页按钮的虚拟值。插件以分页状态判断末页，不把该值当成真实总行数，也不自动执行 COUNT。
- 原页面会翻页，并停在最后读取的页面。收集期间保持来源页面、SQL、结果列和排序不变；查询或列变化时插件停止，避免合并不同查询的数据。
- 没有稳定排序的 SQL，以及查询过程中变化的数据库数据，都可能让不同分页之间出现重复或遗漏。插件保留页面实际返回的行，不擅自去重；需要一致的全量快照时应使用系统支持的数据库导出能力。
- 点击「停止读取」会停止后续翻页。当前已经发出的页面请求可能仍会完成。关闭导出页也会停止后续翻页，但该页内已收集的数据不会保留。
- 达到上限、页面报错、等待超过 30 秒或用户停止时，明确显示「未完成」。可以导出已收集部分，文件名带 `_未完成`，JSON 的 `complete` 为 `false`。提高上限后重新读取会从第 1 页开始，不追加之前的结果。
- 即使读到页面末页，也只代表读完了 CDAS 当前查询允许返回的结果；SQL 的 LIMIT、系统最大条数、权限和后台限制仍然有效。

## 文件格式

- CSV：UTF-8 BOM、CRLF 换行，正确处理中文、逗号、双引号和单元格换行；NULL 输出为空单元格。以公式前缀开头的字符串添加单引号，避免表格软件将数据作为公式执行。
- 复制到表格：带列标题的 TSV，换行或制表符等内容会按表格文本转义，同样保护公式样式的字符串。
- JSON：包含列映射、二维数据数组、实际已收集行数、范围与完成状态。保留页面提供的数字、布尔值、NULL、空字符串及原始文本。`scope: "current"` 表示当前页已读取完成，不代表整个查询的所有分页。

例如 JSON 的 `columns[0]` 对应每一行 `rows[n][0]`。`field` 是页面数据字段，`title` 是表头，因此同名表头也不会覆盖不同字段。

Excel 直接打开 CSV 时可能自动转换长编号、日期和前导零。需要保留这些内容时，使用 Excel 的「数据 → 从文本/CSV」并将相应列设为文本，或使用 JSON 保存原始数据。插件无法恢复在数据到达浏览器之前已经丢失的数值精度。

## 权限和数据

仅申请 `activeTab`、`scripting`、`downloads` 和 `clipboardWrite`。用户点击插件后临时读取该来源标签页；未配置所有网站的常驻访问权限。没有内容脚本、外部库下载、统计、远程服务器、Cookie 读取或账号配置。采集内容只保存在当前扩展页面的内存中，由用户选择保存到本机或复制到剪贴板。

插件包不包含用户提供的内网页面、查询结果、地址或账号资料。

## 常见情况

- **未找到结果**：先运行查询并打开结果页签，再点击「重新识别」。页面已刷新、跳转或重新登录时，从 CDAS 页面再次点击扩展图标。
- **查询窗口是单独标签页或跨域 iframe**：请直接在查询窗口所在标签页点击扩展。当前授权不覆盖任意跨域子页面。
- **只有保存的 HTML**：在扩展详情中开启「允许访问文件网址」，再打开 HTML 并点击插件。此时使用表格文本回退，只能导出已保存当前页的行，无法自动翻页，也无法区分显示为空的 NULL 和空字符串。
- **保存的页面缺失样式或脚本**：插件的文本回退通常仍能读取 `datagrid` 表格；已丢失或未保存的分页数据不会凭空恢复。
- **浏览器由公司管理**：若加载扩展被组织策略禁用，需要通过公司允许的扩展安装方式使用。

## 开发与验证

没有构建步骤；可直接加载 `extension`。格式单元测试使用 Node.js：

```sh
node --test tests/formats.test.mjs
```

浏览器集成测试需要 Node.js、Playwright 与 Chromium，并使用另行提供的 EasyUI 资源目录（包含 `jquery-3.5.0.min.js`、`jquery.easyui.min.js`、`easyui.css` 和保存的 `-1.html`）：

```sh
node tests/browser.mjs /path/to/cdas-resources
```

测试使用本地合成数据验证 iframe、多结果、完整值、冻结列、虚拟总行数、重复行、文件下载、停止、超时、加载失败与查询变化，并单独核对已保存结果页。为了自动化测试，临时复制的测试扩展仅额外授予 localhost 访问权限；交付的扩展不含该权限。

若测试机的管理策略明确禁止加载未打包扩展，测试会使用浏览器 API 桥接模式：在真实 Chromium 页面运行未修改的采集器与导出界面，以测试桥接替代 `chrome.scripting` / `chrome.downloads`，验证数据与浏览器下载。此模式不验证原生扩展的安装、权限和 API 通道，报告会标记 `nativeExtensionLoaded: false`，不会将其描述为扩展加载成功。其他扩展加载错误仍会使测试失败。

本次验证：5 项格式单元测试、17 项浏览器功能检查通过；提供的保存页中 200 行、3 列数据与导出逐格一致。新增检查覆盖键盘展开说明、表格焦点、减少动态效果和 375 / 650 / 768 / 1024 / 1440px 布局。本测试机受管理策略限制，使用了上述桥接模式。测试阻止所有外部网络连接，未连接真实内网服务，也未在真实 Mac Chrome 或内网登录会话中测试。
